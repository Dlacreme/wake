# `wake` — handoff

> Review the wake, not the ocean.

A terminal navigator for changesets you didn't write. Status: **Go rewrite complete, subcommands tested, interactive keybinds need verification at a real terminal.**

---

## 1. The problem

We increasingly ship code generated by AI agents, with heavy QA during and after generation. Reviewing that output in a normal editor is the wrong shape of tool: an editor opens the *whole repository* and makes you hunt for what moved. When you weren't the one writing, you need the inverse — start from what was touched, and treat the rest of the codebase as secondary.

Existing tools each solve a slice and miss the whole:

| Tool | Why it isn't this |
|---|---|
| `git diff` / `git status` | Gives the changed-file list, no navigation |
| `delta`, `difit` | Renders diffs beautifully, but no scoped workspace or search |
| VS Code Source Control panel | Shows changed files, but content search still spans the whole repo |
| GitHub / GitLab PR view | Closest UX match, but requires a branch + PR and a browser |

The gap nothing fills: **search — by filename and by content — scoped to just the changed set.**

## 2. What it is

A Go binary (~700 lines across `git/`, `ui/`, `config/`) wrapping Bubble Tea. Not a diff viewer and not an editor — a *navigator* that ends in `$EDITOR`.

**Two panes.** Left: changed files, most recently touched first, tagged `M`/`A`/`D`/`R`. Right: the diff for that file, or the whole file when it's new.

**Keys**

| Key | Action |
|---|---|
| `enter` | Open in `$EDITOR` at the first changed hunk |
| `v` | Mark file viewed — hides it until its diff changes |
| `ctrl-d` | Toggle diff view / whole-file view |
| `ctrl-g` | Grep **only the changed files**, using whatever you've typed |
| `ctrl-f` | Back to the changed-file list |
| `ctrl-p` | **Peek** — fuzzy-find any file in the repo, read it, `esc` to return |
| `ctrl-r` | Refresh |
| `ctrl-/` | Cycle preview layout (right → bottom → hidden) |
| `↑/k`, `↓/j` | Navigate |
| `q` / `ctrl-c` | Quit |

**Invocation**

```bash
wake                  # vs HEAD: staged + unstaged + untracked
wake --since main     # everything done on this branch
wake --since HEAD~3   # last three commits plus working tree
```

## 3. Decisions already made, and why

Re-litigate these only with new information — each was argued through.

**Terminal, not Electron/web.** Explicit preference. The binary is the product.

**Go + Bubble Tea, not fzf.** The rewrite was triggered by a concrete need: `v` to mark a file viewed and hide it until its diff changes. fzf cannot do per-row persistent state — it regenerates rows wholesale. Bubble Tea holds the list in a Go slice in memory, so hiding a row is `O(n)` slice filter. This is the right seam.

**Viewed marking is session-only.** Not persisted to disk. Rationale: the session *is* the review session. On next `wake`, everything reappears — which is correct, because you want to re-check any files that changed overnight. The `viewed` map uses `path → sha256(diff)`: if the diff changes while wake is open, the file reappears on next refresh.

**Peek is a mode switch, not a subprocess.** The bash version used fzf's `execute()` trick to suspend the parent fzf. In Bubble Tea, peek is just `mode = ModePeek` with its own cursor/query fields. Returning (`esc`) is `mode = ModeList` with the saved cursor restored. Same UX, cleaner implementation.

**Diff against `HEAD`, not the index.** A plain `git diff` shows nothing for staged-only changes. Diffing `HEAD` catches the work whether or not the agent staged it.

**New files preview as whole files, not diffs.** The diff of a new file is "everything added," which is noise when you have no mental model of it. `ctrl-d` gives the reverse toggle for modified files.

**Sub-second mtimes for recency sort.** Uses `syscall.Stat` directly (platform-split build files: `mtime_bsd.go`, `mtime_linux.go`, `mtime_other.go`).

**bat/delta remain optional runtime deps.** The Go binary does not embed a syntax highlighter. When `bat`/`delta` are absent it falls back to plain `git diff` / `cat -n`. This keeps the install story simple and respects users' existing rendering preferences.

**Config is flat TOML.** Rationale in the original design: flat TOML is ~20 lines of Go to parse and stays forward-compatible if more structure is ever needed. No migration required.

## 4. Architecture

```
main.go              parse flags, validate ref, "nothing changed" fast-path, launch TUI
config/
  config.go          Load() → merge defaults + ~/.config/wake/config.toml + .wake.toml + env
git/
  git.go             Root, ValidateRef, ChangedItems, GrepItems, GrepAll, RepoFiles,
                     DiffText, FileText, HunkLine, DiffHash
  mtime_bsd.go       sub-second mtime for macOS/BSD (build tag: darwin|freebsd|...)
  mtime_linux.go     sub-second mtime for Linux
  mtime_other.go     fallback via os.Stat
ui/
  keys.go            key.Map (all bindings in one place)
  preview.go         renderPreview → shells to bat/delta or plain fallback
  model.go           Bubble Tea Model: Init / Update / View
```

**Line format (internal):** `git.Item{Status, Path, Line, Text}`. Status chars: `M` modified, `A` added, `D` deleted, `R` renamed, `P` plain (peek), `G` grep hit.

**State.** Held in the Bubble Tea `Model` struct — no temp files, no env var tricks. `viewed map[string]string` is path → diffHash. `full bool` is the diff/full toggle. `mode Mode` drives the layout and key handling.

**Env vars:** `WAKE_SINCE`, `WAKE_EDITOR_LINE_FMT`, `EDITOR`.

## 5. Install

```bash
# from source
cd wake && go build -o ~/.local/bin/wake .

# optional but recommended
brew install bat delta ripgrep

export EDITOR=nvim   # in ~/.zshrc
```

Editors receiving a correct line number: vim, nvim, vi, view, code, code-insiders, codium, cursor, windsurf, subl, sublime_text, hx, helix, emacs, emacsclient, nano, micro. Anything else gets the file without a line, unless `WAKE_EDITOR_LINE_FMT` is set.

**Config file** (`~/.config/wake/config.toml` or `.wake.toml` in repo root):

```toml
editor         = "nvim"
editor_line_fmt = ""          # e.g. "--goto {file}:{line}"
since          = ""           # default base ref
preview        = "diff"       # "diff" | "full"
preview_width  = 62           # percent
sort           = "mtime"
exclude        = ["*.lock", "dist/**", "*.snap"]
```

**Test fixture:**

```bash
./test-fixture          # builds /tmp/wake-fixture with all 6 change states
cd /tmp/wake-fixture && wake
```

## 6. Testing done

**Subcommands (Go):** `git.ChangedItems`, `git.GrepItems`, `git.RepoFiles`, `git.DiffHash`, `git.HunkLine` all verified against the fixture repo (all 6 change states: unstaged edit, staged edit, untracked, staged new, deletion, rename, path with spaces).

**Fast-paths:** "nothing changed" exits cleanly; "not a git repo" exits with error; bad `--since` ref rejected before TUI launches.

**Cross-platform build:** macOS arm64 (native) and Linux amd64 (`GOOS=linux`) both compile clean.

**Not yet tested:** interactive TUI behaviour. A terminal is required — the Bubble Tea program cannot run without a TTY. Every keybind needs a human at a terminal. Use `test-fixture` to set up the scenario.

### Bugs from the bash era, carried over as fixed

- `rg`/`grep` `-H` flag: both suppress filename with a single-file input. Fixed by always passing `-H`.
- Peek-grep hung when stdin wasn't a TTY. Fixed with explicit `.` path and `</dev/null`.
- Recency sort collapsed under equal mtimes. Fixed with nanosecond `syscall.Stat`.
- Bad `--since` ref leaked git stderr. Fixed with upfront `git rev-parse --verify`.

## 7. Where we stand / what's next

**The rewrite decision is closed.** Viewed/session marking required per-row state that fzf cannot hold. The Go + Bubble Tea rewrite delivers it cleanly and drops the fzf runtime dependency.

**Use it for a week before adding anything.** The next feature should be chosen from real friction on a real 40-file changeset.

**Refresh model — still open.** Today `ctrl-r` is manual. Options: (a) header notification `+3 changed — ctrl-r`, never moving the cursor; (b) auto-reload every ~2s with cursor preserved. Leaning (a): cheapest, least disruptive mid-read.

**`exclude` globs are wired and working.** Worth configuring early — agent changesets are full of lockfiles, snapshots and generated output.

**Smaller open questions.**
- Should peek remember its last query? Currently resets on every `ctrl-p`.
- Should `enter` in peek close it (return to list) or keep it open for multi-file inspection? Currently keeps it open.
- Viewed state is session-only. If persistence becomes useful, a `~/.local/share/wake/viewed` file keyed by `repoRoot+path+diffHash` would be the natural place — no schema change needed.
